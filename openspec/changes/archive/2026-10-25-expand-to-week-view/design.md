# Design

## Context

- 表示する日は `src/view/clock.ts` の `getViewState(now)` が `today` / `tomorrow` / `todayClosed` / `nextBoundary` として返し、`src/view/render.ts` の `render()` が `dayHtml()` で2枚のカードを `innerHTML` に組み立てている
- 収集日の判定は日ごとに `getCollection(date)` を呼ぶだけなので、7日分に増やしても判定ロジック（`collection-schedule`）は変えなくてよい
- 再描画のタイミング（`nextBoundary` = 今日の8:00 または翌日0:00、と `visibilitychange` / `pageshow`）は、1週間の範囲も「日付が変わるとき」にしか動かないので、そのままでよい
- テストは Vitest（Node 環境、DOM なし）。`clock.ts` と `install-hint.ts` の純粋な関数だけをテストしている
- 種類の表示名は最長で「新聞紙、雑誌・雑がみ、段ボール、牛乳パック類、古着」と長く、そのままでは1行に収まらない

## Goals / Non-Goals

**Goals:**

- 今日・明日のカードはこれまでの見た目と操作をそのまま保つ
- 2〜6日後は1日1行で、種類が色とアイコンでひと目で分かる
- 1週間分の日付の計算と行の中身をテストできるようにする

**Non-Goals:**

- コンパクトな行での品目例の開閉（必要になったら別の変更で検討する）
- 表示日数をユーザーが切り替える設定
- 週単位のページ送りや、7日より先の表示

## Decisions

### 1. `ViewState` は `tomorrow` をやめて `days: CalendarDate[]`（7要素）にする

`days[0]` が今日、`days[1]` が明日、`days[6]` が6日後。日数は `clock.ts` に `DAYS_SHOWN = 7` として定数で持つ。`today` は `days[0]` と同じになるので残さない（呼び出し元は `render.ts` だけ）。

- 代替案: `today` / `tomorrow` を残して `upcoming: CalendarDate[]`（5要素）を足す → 今日・明日だけ特別扱いする型になり、日付計算が2か所に分かれる。描画側で「先頭2つはカード」と決めるほうが単純

日付は `new Date(y, m, d + i)` で作る（既存の明日の計算と同じ方法。月末・年末の繰り上がりとローカル時刻を `Date` に任せる）。

### 2. コンパクトな行は `<ol class="week">` の `<li>` で描画する

カード2枚のあとに「この先の予定」という小見出しを付け、5日分を順序付きリストで並べる。各行は左に日付と曜日（固定幅）、右に種類のチップを `flex-wrap` で並べる。種類がないときは「収集なし」を薄い文字で出す。

- チップ: 種類の色（既存の `--cat-*` 変数と `.cat-<id>` クラスを再利用）を背景に、小さいアイコン（20px程度）と短い名前
- 特別収集: チップの中に小さな「特別」バッジ
- 推定: 行の右端に小さな「推定」バッジ（`--warn-bg` / `--warn-text` を再利用）。カードの長い注記は今日・明日だけに出す
- 1日あたりの種類は通常最大2つ（第1・第3木曜のプラスチック製容器包装＋燃やせないごみ）で、特別収集が重なっても `flex-wrap` で折り返すので横スクロールは起きない

代替案: 7列のカレンダー表 → iPhone幅では1マスが約45pxになり、色だけで種類を判別することになる。行のほうが読みやすい。

### 3. 種類に短い名前 `shortName` を追加する

`Category` に `shortName` を足し、`categories.ts` で定義する。

| id | shortName |
| --- | --- |
| burnable | 燃やせる |
| nonBurnable | 燃やせない |
| plastic | プラ |
| cansBottles | 缶・びん・ペット |
| paperClothes | 古紙・古着 |
| metal | 金属類 |

- 代替案: アイコンだけ → 燃やせる／燃やせないのアイコンが似ていて、家族が見て迷う。短い名前を添える

### 4. HTML 組み立てを文字列を返す関数に分けてテストする

`render.ts` の中身を `weekHtml(state): string`（DOM に触らない）と、それを `root.innerHTML` に入れる `render()` に分ける。Node 環境のままで、`weekHtml` の出力に対して「7日分の日付が順に並ぶ」「推定・特別・収集なしの表示」を文字列で確かめるテストを書ける。DOM 環境（jsdom など）の依存は追加しない。

## Risks / Trade-offs

- [今日・明日の下に行が増え、ホーム画面追加の案内（画面下に固定表示）が最後の行に重なる] → `#app` の下余白を案内の高さぶん確保するか、案内を閉じれば見えることを確認する。実機（iPhone Safari）で確認するタスクを入れる
- [今日が収集のある日で品目例を開くと、カードが伸びてコンパクトな行が画面外に出る] → 既存と同じく品目例は初期状態で閉じているので、通常は問題にならない。スクロールで見られれば要件は満たす
- [短い名前「プラ」などが公式の呼び方と違う] → 今日・明日のカードでは正式名を出し続けるので、確認したいときは当日・前日に正式名を見られる

## Migration Plan

いつもどおり `main` にマージすると GitHub Actions で Pages にデプロイされ、PWA は `autoUpdate` で次回以降の起動に反映される。データの移行はない。戻すときはマージしたコミットを revert する。
